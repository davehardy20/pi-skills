# GLOSSARY.md Format

`GLOSSARY.md` is the canonical language for a teaching workspace. Lessons,
reference documents, and learning records should use its terms consistently.
Building the glossary is part of learning: a tight definition is evidence that a
concept has started to compress.

## Template

```md
# {Topic} Glossary

{One or two sentences describing the topic this glossary covers.}

## Terms

**{Term}**:
{One or two sentences defining what the term is.}
_Avoid_: {loose synonym, misleading term, alias to avoid}

**{Another term}**:
{Definition.}
_Avoid_: {optional aliases to avoid}
```

## Rules

- **Add a term only when Dave understands it.** The glossary records compressed
  knowledge; it is not a dictionary dump.
- **Be opinionated.** Pick the best term and list aliases to avoid when useful.
- **Keep definitions tight.** Define what the term is, not a full procedure.
- **Use existing glossary terms inside definitions.** This makes later concepts
  easier to absorb.
- **Group naturally.** Add subheadings when clusters emerge. A flat list is fine
  when terms cohere.
- **Resolve ambiguities.** If the wider field uses a term loosely, state the
  workspace meaning.
- **Revise in place.** If understanding deepens, improve the definition rather
  than leaving stale wording.
